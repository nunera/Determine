# Determine wire protocol v1

Single source of truth for every byte exchanged between the two wearable boards and the phone. Implementations:

| Language | File | Used by |
|---|---|---|
| Python (reference) | `protocol/python/determine_wire.py` | simulator, golden vectors |
| C | `firmware/common/include/determine_wire.h` | cue board, camera board |
| Kotlin | `phone/core/src/main/kotlin/.../wire/` | phone core, Android app |

Golden vectors (`protocol/vectors/vectors.json`) are generated by the Python reference (`protocol/gen_vectors.py`). Every other implementation MUST decode each vector to the listed fields and re-encode it to the identical bytes.

## Transport

- UDP over the phone's Wi-Fi hotspot. All integers **little-endian**. No padding.
- Phone listens on **47000**. Cue board (XIAO ESP32-C3) listens on **47001**. Camera board (ESP32-CAM) listens on **47002**.
- Boards send to their DHCP gateway (the phone hotspot) on port 47000. The phone learns each board's IP from its first packet.
- Clocks: board time is `esp_timer_get_time()` in µs since boot. Phone time is its monotonic clock in µs.

## Header (8 bytes, every packet)

| Offset | Field | Type | Notes |
|---|---|---|---|
| 0 | magic | u16 | `0x5444` (bytes `44 54`, "DT") |
| 2 | ver | u8 | `1` |
| 3 | type | u8 | see below |
| 4 | seq | u32 | per-sender counter, wraps. Board packets: per type. **Phone → cue board commands (CUE and PROFILE) share ONE counter** so every ACK maps to exactly one command; receivers must not assume consecutive seqs |

Receivers drop packets with wrong magic, wrong version, unknown type or wrong length.

## Types

| Type | Name | Direction | Body bytes | Total |
|---|---|---|---|---|
| 0x01 | BEAT | board → phone | 16 | 24 |
| 0x02 | RANGE | cue board → phone | 204 | 212 |
| 0x03 | FRAME | camera board → phone | 30 + chunk_len | ≤ 1438 |
| 0x10 | PING | phone → board | 8 | 16 |
| 0x11 | PONG | board → phone | 24 | 32 |
| 0x20 | CUE | phone → cue board | 26 | 34 |
| 0x21 | ACK | cue board → phone | 16 | 24 |
| 0x22 | PROFILE | phone → cue board | 4 | 12 |

### BEAT 0x01 — 10 Hz from each board

| Field | Type | Notes |
|---|---|---|
| board | u8 | 1 = CAM, 2 = CUE |
| reset_reason | u8 | `esp_reset_reason()` value at boot |
| faults | u16 | bit flags, below |
| t_us | u64 | board time at send |
| rssi_dbm | i8 | Wi-Fi RSSI |
| temp_c | i8 | 127 = unknown |
| heap_kb | u16 | free heap |

Fault bits: 0 SENSOR_INIT_FAIL · 1 SENSOR_READ_ERR · 2 I2S_ERR · 3 HAPTIC_L_ERR · 4 HAPTIC_R_ERR · 5 BROWNOUT_SEEN · 6 NO_CLOCK_SYNC · 7 WATCHDOG_ACTIVE · 8 LOW_HEAP · 9 CAPTURE_FAIL.

### RANGE 0x02 — 15 Hz from the cue board

| Field | Type | Notes |
|---|---|---|
| t_us | u64 | board time when the sensor reported the grid |
| res | u8 | 64 (8×8) |
| reserved | u8 | 0 |
| reserved | u16 | 0 |
| mm | u16[64] | distance per zone |
| status | u8[64] | per zone |

Zone index = `row * 8 + col`, **row 0 = top of the wearer's view, col 0 = wearer's left**. Firmware applies the mounting transform before sending.

Status: the raw VL53L5CX `target_status`, except **255 = NO_TARGET** (sensor saw no target; `mm` = 0). Phone rules: 5 and 9 are VALID; 255 is NO_TARGET (nothing within range, counted for confidence); anything else is UNKNOWN and never "far".

### FRAME 0x03 — JPEG in chunks

| Field | Type | Notes |
|---|---|---|
| frame_id | u32 | increments per frame |
| t_cap_us | u64 | board time of capture |
| w | u16 | pixels |
| h | u16 | pixels |
| total_len | u32 | JPEG bytes |
| offset | u32 | of this chunk |
| chunk_len | u16 | ≤ 1400 |
| chunk_idx | u16 | 0-based |
| chunk_count | u16 | |
| data | u8[chunk_len] | |

The phone drops any frame not complete within 150 ms of its first chunk, and any frame older than the freshness bound.

### PING 0x10 / PONG 0x11 — clock sync, 10 Hz per board

PING: `t_phone_us u64`. PONG: `t_phone_us u64` (echo), `t_board_rx_us u64`, `t_board_tx_us u64`.

Phone computes (NTP-style), with `t4` = phone receive time:
`offset = ((rx − t_phone) + (tx − t4)) / 2` (board − phone), `rtt = (t4 − t_phone) − (tx − rx)`. Keep the offset from the lowest-RTT sample in a sliding window.

PING also serves as the phone's liveness signal to the cue board (watchdog).

### CUE 0x20

| Field | Type | Notes |
|---|---|---|
| t_issued_phone_us | u64 | phone time at send (logging) |
| deadline_board_us | u64 | phone's estimate of board time at issue + ttl; **0 = no sync** |
| cue_id | u8 | table below |
| side | u8 | 0 L, 1 R, 2 BOTH |
| gain_l_db | i8 | dBFS, ≤ 0; −128 = mute |
| gain_r_db | i8 | dBFS, ≤ 0; −128 = mute |
| haptic_pattern | u8 | table below |
| haptic_l | u8 | 0–255 |
| haptic_r | u8 | 0–255 |
| flags | u8 | bit0 = interrupt current sound |
| ttl_ms | u16 | |

The cue board drops a CUE if `deadline_board_us == 0` or `now > deadline_board_us` (ACK EXPIRED / NO_SYNC). It clamps each gain to `min(profile.ceiling_db, FW_HARD_CEILING_DB)` independently of the phone (ACK PLAYED_CLAMPED when clamping changed a value). The phone drives repetition: one CUE per repetition.

### ACK 0x21

`cue_seq u32` (the CUE or PROFILE header seq; unique because the phone draws both from one counter), `status u8` (0 PLAYED, 1 EXPIRED, 2 PLAYED_CLAMPED, 3 NO_SYNC, 4 BAD_CUE, 5 BUSY_DROPPED), `reserved u8`, `applied_gain_l_db i8`, `applied_gain_r_db i8`, `t_board_us u64`.

### PROFILE 0x22

`ceiling_db i8` (dBFS), `mode u8` (0 STEREO, 1 SSD, 2 HAPTIC_ONLY), `haptic_max u8`, `reserved u8`. The board can only lower its ceiling below `FW_HARD_CEILING_DB` (−10 dBFS, PROPOSED until the transducers are characterised). HAPTIC_ONLY mutes audio on the board. Acknowledged with ACK status 0.

## Cue IDs

| ID | Name | Sound (synthesised on the cue board) |
|---|---|---|
| 0 | READY | one soft tick |
| 1 | OBSTACLE_FAR | wood-block double |
| 2 | OBSTACLE_MID | wood-block double |
| 3 | OBSTACLE_NEAR | one sharper urgent note |
| 4 | PERSON_FAR | two-tone marimba rising |
| 5 | PERSON_MID | two-tone marimba rising |
| 6 | PERSON_NEAR | one sharper urgent marimba note |
| 7 | SYSTEM_OFF | three descending notes |
| 8 | CAL_TONE_500 | 300 ms 500 Hz tone |
| 9 | CAL_TONE_1K | 300 ms 1 kHz tone |
| 10 | CAL_TONE_2K | 300 ms 2 kHz tone |
| 11 | CAL_OBSTACLE | wood-block double (balance step) |

Timing rule (Arch §8.1): every note ≥ 83 ms; whole cue fits its repetition period with a ≥ 100 ms gap; ≤ 6 notes/s.

## Haptic patterns

0 NONE · 1 PULSE40 (40 ms) · 2 PULSE60 (60 ms) · 3 BUZZ150 (150 ms) · 4 LSS (400 ms on, 100 off, 120 on, 100 off, 120 on).

## Watchdog

The cue board enters WATCHDOG when no PING arrives for 800 ms (or none within 5 s of boot). It then plays SYSTEM_OFF plus haptic LSS every 5 s at `min(ceiling, −20 dBFS)` and sets fault bit 7, until PINGs resume.

## Rates and bounds (PROPOSED, tuned at Gates G6–G7)

| Item | Value |
|---|---|
| RANGE | 15 Hz |
| BEAT | 10 Hz per board |
| PING | 10 Hz per board |
| FRAME | 10–15 fps, QVGA–VGA JPEG |
| Phone freshness bound | 500 ms frame age; 500 ms without BEAT → UNAVAILABLE |
| CUE ttl | 150 ms (repeat cues), 1000 ms (calibration) |
